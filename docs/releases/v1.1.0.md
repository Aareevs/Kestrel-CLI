# Kestrel v1.1.0

> **Status: prepared, not released.** Nothing below has been tagged or published. The owner decides when (see
> [releasing.md](../releasing.md)). Until then this is what the release would say.

v1.1.0 makes Kestrel recognize more stacks, nicer to use at a terminal, easier to wire into agents and CI, and
better at telling you why something failed. It is backward compatible for scripts except for the changes under
**Upgrade notes**.

## Highlights

**More stacks.** Failure patterns for Java and Kotlin, Rust, .NET, Ruby/Rails, PHP/Laravel, and Docker/Compose.
`kestrel inspect` now understands Elixir/Phoenix, .NET, Deno, Bun, Expo / React Native, and monorepos (pnpm, npm,
yarn, Bun, Go and Cargo workspaces). What each stack gets is in the [ecosystem matrix](../ecosystems.md).

**Your own shapes.** Add a `patterns:` entry to `kestrel.yaml` to teach Kestrel a log line from your stack, with
example lines that `kestrel config validate` checks. [Extending Kestrel](../extending.md) covers that and the
three code-level extension points.

**A better terminal.**
- `kestrel` alone shows a welcome screen with a live project summary and tips that fit it.
- `kestrel watch` pins a service table above the scrolling log.
- `-i` opens an arrow-key picker for the session and incident (`diagnose`, `timeline`, `verify`, `sessions show`).
- `why` is an alias for `diagnose`; `-I N` looks at one incident; `-a`, `-s`, `-w`, `-n` shorten common flags.
- Grouped `--help`, width-aware output, and a `next:` hint on errors.

**Agents.** `kestrel mcp init --client claude-code|cursor|vscode` writes the config for you (merging, never
clobbering). New read-only tools: `list_sessions`, `search_events`, `validate_config`, and an `incident` argument on
the diagnosis and timeline tools.

**CI.** `kestrel verify --format markdown|junit`, or `--markdown FILE` / `--junit FILE` next to the normal output.
`kestrel schema diagnose|timeline|verify` prints a JSON Schema (draft 2020-12) for the `--json` output. Examples for
GitHub Actions and GitLab are in [verification.md](../verification.md#in-ci). (There is no Kestrel GitHub Action.)

**Better diagnoses.** Dogfooding on real projects and real tools failing found and fixed bugs that unit tests had
not: a missing module is now explained before the generic "failed during startup"; a port held by another service of
the same session is named; a crashed process's last lines are quoted when no pattern matched; a dependent's
continuing refusals stay in one incident; and Python's buffered output no longer hides banners and last errors.

**Security.** Two redaction gaps are closed (`redis://:password@host`, an AWS secret key written in prose), and
stored text is now redacted with *today's* rules wherever it is printed, not only on export and over MCP.

## Upgrade notes

1. **`kestrel verify` can now exit 3.** If everything that ran passed but a check you configured did not run (most
   often a `command` check without `--allow-exec` in a script or CI), the verdict is `inconclusive` and the exit code
   is 3, where it used to be `resolved` and 0. Pass `--allow-exec` for a config you trust, or remove the check. A
   failing check is unchanged.
2. **Incidents can be split differently.** A time-only incident is at most one correlation window long, so a long
   session with unrelated errors reports several incidents where it used to report one large weak one.
3. **Kestrel sets `PYTHONUNBUFFERED=1`** for Python services it starts. Set it yourself (an empty value turns it
   off) if you need different behavior.
4. **More events for a steady repeating error:** one summary every 2s instead of per run. Storage grows by a few
   events, not per line.
5. **Old sessions:** text already stored keeps what the older redaction rules left. Output is re-redacted when
   printed, but if a secret in one of the two newly closed formats matters, delete that session
   (`kestrel sessions delete <id>`).
6. `kestrel` with no arguments at a terminal shows the welcome screen; scripts are unaffected (not a terminal).

## How this was verified, and what wasn't

Run locally on macOS (darwin/arm64, Go 1.26.2) for every change, with `gofmt`, `go vet`, `go test`, `go test -race`,
`staticcheck`, and cross-builds including `GOOS=windows go vet`. Coverage is 88.1% of statements in short mode. A
local release snapshot (`make release-snapshot`) builds all five platform archives, and the snapshot binary runs.
Important tests were mutation-checked (the code broken on purpose to confirm the test fails), and timing-sensitive
tests were run repeatedly under CPU load with the race detector.

**CI:** one pre-release CI run (GitHub Actions run `43172507708`) passed on macOS, Ubuntu and Windows. It found one
wrong test, not a product bug: the pinned-table `watch` test expected the table on Windows, where it is off by design,
so it now skips there. Not done: the pinned `watch` table was checked
through a pty and an emulator, not by eye in every terminal app. The GitHub Actions and GitLab examples were run as
shell, not on real runners.

## Known limits

See "Limits" in each pull request (#11-#30) and [PROGRESS.md](../PROGRESS.md). The main ones: the pinned status table
is off on Windows; `search_events` is a substring scan; weak incidents are bounded to one window, so a slow cascade
of unrelated-looking failures is several incidents; the quoted "last output" of a crashed process is a heuristic and
is marked unrecognized; only `diagnose`, `timeline` and `verify` have schemas.
